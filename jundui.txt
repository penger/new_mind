### 四、 针对图数据库（Graph DB）建模的格式说明

在你的 D3.js 或 Neo4j 建模中，建议按照以下 JSON 格式处理上述数据，以解决你提到的“一对多”无力感：

```json
{
  "nodes": [
    {"id": "H11_D32", "label": "Unit", "name": "红11军第32师", "type": "RedArmy"},
    {"id": "H1_D2", "label": "Unit", "name": "红1师第2师", "type": "RedArmy"},
    {"id": "Z_W_J", "label": "Person", "name": "周维炯"}
  ],
  "edges": [
    {
      "source": "H11_D32",
      "target": "H1_D2",
      "relation": "REORGANIZED_INTO",
      "properties": {
        "date": "1930-03",
        "event": "鄂豫皖红军整编"
      }
    },
    {
      "source": "Z_W_J",
      "target": "H11_D32",
      "relation": "COMMANDED",
      "properties": {"role": "师长"}
    }
  ]
}
```

### 💡 技术建议：
1.  **处理“分拆” (1:N)：** 比如 115 师分出晋察冀军区。在数据库中，你应该创建两条边：`115师 -> [:BRANCHED_OUT] -> 晋察冀军区` 和 `115师 -> [:REMAINED] -> 115师主力`。
2.  **处理“合并” (N:1)：** 比如 51 师、58 师合成 74 军。应为两条入边：`51师 -> [:MERGED_INTO] -> 74军` 和 `58师 -> [:MERGED_INTO] -> 74军`。
3.  **时间轴渲染：** 在 D3.js 中，通过点击时间轴动态过滤 `properties.date` 属性，你可以清晰地看到原本混乱的番号是如何在历史长河中“流动”并最终汇聚成庞大军团的。

这份详细的清单涵盖了从商城起义开始的鄂豫皖主轴，以及抗战期间最核心的番号变动，足以支撑你构建一个复杂的动态知识图谱。
